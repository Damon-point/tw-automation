# tw-next — TW Automation 새 화면 (Next.js)

기존 시스템(`tw-automation`, 8080)의 화면을 Next.js 로 다시 만든다. **tw-automation 폴더는 고치지 않는다.**

```
 브라우저 ──▶ web (Next.js 15, 3080) ──/api──▶ api (FastAPI, 8180, 127.0.0.1)
                                                  │  import 만
                                                  ▼
                                   tw-automation 의 코드 · tw_app.db · work/  (읽기만)
```

- `api/` — 기존 코드의 함수(회차·작업·단계·제품·메일)를 불러 JSON 으로 준다. 로그인은 기존 계정의 비밀번호로.
- `web/` — 화면. `/api/*` 는 API 로 넘겨 같은 주소에서 세션 쿠키가 붙는다.

## 1단계 — 보기 전용 (지금)

단계 실행 · 검수 · 업로드 · 발송은 **아직 8080 에서** 한다. 진행률이 8080 프로세스 메모리에 있어서, 두 서버가
같은 단계를 돌리면 화면이 "실행 중" 으로 굳는다(2026-10-07 사고). 새 화면은 그 자리로 바로 가는 링크를 준다.

| 화면 | 주소 | 하는 일 |
|---|---|---|
| 오늘 할 일 | `/` | 결재 대기 → 실패한 단계 → 검수 대기 → 실행 중 → 신규 회차 |
| OS Update | `/rounds` | 진행 중 · 최근 완료 회차, 검색(`/` 키) |
| 작업 상세 | `/jobs/{id}` | 핵심 사실 · 두 갈래 단계 · RN 체크 · Dropbox 링크 · 결과물 · 근거 메일 |
| 메일 | `/mail` | 최근 메일, 회차 근거 메일 종류 표시 |
| 제품 관리 | `/products` | 단계가 쓰는 경로·문서 주소의 채움 상태 |

## 사용자 편의 — 무엇을 왜 바꿨나

이번에 실제로 겪은 불편에서 나왔다.

1. **홈 = 오늘 할 일.** 예전 첫 화면은 회차 목록이라, 결재 요청이나 실패한 단계를 찾으려면 작업을 하나씩 열어야 했다.
2. **결과 글 요약.** 단계 결과는 수십 줄짜리 글이다. ✘(오류)·⚠(경고) 줄만 위로 뽑아 색으로 보이고 원문은 접는다.
   "Release Note 링크를 얻지 못했습니다" 같은 오류가 홈에서 바로 보인다.
3. **막힌 이유를 단계 옆에.** "앞 단계 '…' 가 아직 완료되지 않음". 실행 버튼이 왜 안 눌리는지 찾지 않아도 된다.
4. **핵심 사실을 작업 맨 위에.** 공식 버전 · 버전 표기 · 빌드 날짜 · 이전 버전 · RN for Sales 링크 · 승인일.
   86.07C8 표기, RN 링크, 이전 판처럼 사고가 났던 값들을 처음에 확인할 수 있다.
5. **Release Note 체크리스트.** 1차 승인 → 전체 이력 PDF → 2차 검수 → for Sales PDF → 파일서버 보관.
   PM352 · PM452 처럼 2차 검수 없이 넘어가 for Sales 가 빠진 것을 바로 알 수 있다.
6. **Dropbox sdcard 링크를 한 곳에.** FULL/DIFF 와 이름이 보여서 07 · 07C1 DIFF 가 섞인 것을 한눈에 본다.
7. **"다음 할 일" 표시.** 각 갈래에서 지금 돌 차례인 단계를 표시한다.
8. **실행 중이면 자동 새로고침**(4~5초), 아니면 30초.
9. **모바일 · 다크 모드**, 검색 단축키(`/`).

## 2단계 — 쓰기 이관 (계획)

쓰기를 옮기려면 단계 실행이 한 곳에서만 일어나야 한다. 두 길이 있다.

- **A. 8080 을 끄고 tw-next 로 넘어간다.** 단계 실행·진행률을 API 프로세스가 맡는다(기존 함수 그대로). 화면은 실행 ·
  중단 · 검수 · 되돌리기 · 업로드 확인 대화상자를 이 쪽으로 옮긴다.
- **B. 둘을 한동안 같이 쓴다.** 진행률을 메모리가 아니라 DB 로 옮겨야 한다 — 기존 코드를 고쳐야 하므로 tw-automation 을
  손대지 않는 조건과 부딪친다.

다음으로 옮길 쓰기 후보(자주 쓰고 실수가 났던 것 먼저): 검수 완료/되돌리기 → 실제 업로드 확인 → 단계 실행·중단 →
결재 요청·승인 → 신규 작업 시작.

## 실행

```powershell
# 처음 한 번
cd web; npm install; npx next build
# 띄우기 (콘솔 창 없이)
powershell -ExecutionPolicy Bypass -File scripts\start.ps1
```

- 화면: `http://192.168.121.35:3080` (사내망). 방화벽에 3080 허용 규칙이 있어야 다른 PC 에서 열린다.
- API 는 `127.0.0.1:8180` 에만 열린다. 설정은 `.env`(`TWN_SECRET` 세션 서명 열쇠, `TWN_LEGACY_URL`).
- 개발용 로그인 `TWN_DEV_LOGIN_AS` 는 화면 확인용이다. 이 PC 에서 API 로 직접 보낸 요청만 받고,
  화면 서버를 거친 요청은 거부한다. 운영 실행(`start.ps1`)에서는 켜지 않는다.
